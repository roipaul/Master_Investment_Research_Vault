# Research process: what Claude remembers (copy of 2026-11-26)

A copy of Claude's memory notes on Paul's research agent and skill pipeline. Each line is something Paul stated. The live notes are in Claude's memory; this copy does not update itself.

- Building an investment research agent for "top of the funnel" research — initial read of a company's filings, competitive landscape, etc.
- Can already produce full company primers (e.g. Pool Corporation) from cited sources; the primer is built primarily on top of the SEC database and XBRL
- Goal is a system where facts and observations are reusable building blocks across companies (customers, competitors, suppliers), not a one-off primer writer
- Considering Nasdaq Data Link SF1 (Sharadar fundamentals) as an additional data source alongside the SEC database; wants infrastructure that handles interconnected qualitative and quantitative information
- Aug 2026: going with Claude's recommended design leans for the system architecture (claims/docket layer over standardized series), with Postgres (+pgvector) as the system of record — but as of Sep 2026 has NOT decided to actually build the Postgres data layer, and wants it kept separate from his notes vault; Sep 2026: requested and received a detailed architecture spec (draft v0.1, research-system-spec.md) covering identity model, series/spans/claims/docket/judgment schemas, MCP write contract, playbooks, monitoring, and a six-milestone build order
- Aug 2026 post-mortem on the first version of the system: over-engineered (memory, eval, graph DB, embeddings, complex skills) with too tight a harness; all research outputs went to one markdown that went stale because fast- and slow-moving data were mixed; data management across sources (CIQ via a Playwright pipeline, SEC database for filings, Alpha Vantage for transcripts) was poorly designed and hard to re-engineer — rebuilding around a data system that ingests, stores, and links quantitative and qualitative data as the research backbone
- Aug 2026 scope: target universe is hundreds to thousands of companies — wants the system to become his research infrastructure, both driving top-of-funnel research and acting as a copilot for deep dives; wants analytical help beyond business description (off-the-shelf models already describe businesses well) but not position-level; still debating the output form; needs more than 5 years of history but not 30
- Aug 2026: starting with US coverage, global coverage the eventual goal — no CIQ API access (website access only, could go away at any time); plans ~100 deep dives this year
- His deep dives end in a written judgment set, built from a good understanding of the business; Alpha Vantage remains his current transcript source
- Sep 2026: a data layer is now implemented in the pipeline (not Postgres) — SEC companyfacts + iXBRL ingestion into a per-observation store with "W7" series materialization to Parquet, run on POOL so far — and is being redesigned around batch Parquet raw_facts → mapping/overrides → certified_facts → series materialization; whether to buy SF1 is undecided (exploring a companyfacts-only build)
- Sep 2026: wants the agent to also do idea generation — screen a broad stock universe on his quality/value criteria using filings (multi-year where needed) and current market price; quality = earnings quality, earnings growth, the underlying reasons for both, and confidence in those reasons; value = valuation gap close plus long-term compounding
- Oct 2026: wants a Claude skill called "/full-primer" that, given a ticker, generates a full company primer in the same four-part format as his existing primers (Company Overview → Company Logistics → Industry Overview → Financial Overview, cited, ~35–50 pages)
- Late Oct 2026: wants the primer to end with an extra section listing the questions to answer before forming a view plus further research and companies to study; and two follow-on skills — "/thesis-debate" (researches the High-materiality questions, bull and bear case per question, a verdict on which side is more likely with probability and confidence, then a final call on the thesis or "inconclusive"; verdict is on the business, valuation only as a closing price check against his 15% IRR hurdle, no price target; output a separate doc in his pitch order) and "/primer-triage" (after a primer, decide Dig / Defer / Drop: stock candidacy first, learning value second; business-quality fail is the only hard knockout; price enters only as timing; edge and timing rank above learning; a Defer must carry a trigger, revisit date, signals to track and a watchlist/vault log entry; Dig produces a research plan before the thesis debate; he confirms each verdict himself)
- Nov 2026: also wants a skill to turn a full primer into shorter "abridged" primers (he has existing abridged examples, ~10 pages, four sections: How the Business Works, Market Position and Competitive Landscape, Industry Dynamics and Strategic Drivers, Key Risks and Growth Levers)
- Nov 2026: asked for and adopted a "/variant-view" skill (identify variant views vs what the price implies, track evidence and conviction per key question), then had a value-trap check added to it and agreed to an edge gate before primers, an exit review when a view gets priced in, and time limits on show-me views
- Nov 2026: his research flow as he describes it — /full-primer and /abridged-primer → /primer-triage → /value-dcf-model → /thesis-debate → /thesis-writeup → /variant-view, then Daloopa earnings-prep and earnings-review to track; says he needs guidance developing views, and for names that need no variant view wants a better screen and a process centred on ruling out value traps
- Nov 2026: going ahead with a reordered /variant-view (price frame before the debate), a workshop mode for developing views, and a separate price-alone track; decision record settled as record-only (it logs his own decision, never recommends) with one rule set, no separate limits for his own and family accounts; screening data to come from his Capital IQ and Visible Alpha access (no API or MCP services)
- Nov 2026: now uses the /research-flow orchestration skill with his GitHub vault as the state store; ran it first on YMM, for which he has a previously run primer he wants reused
- Nov 2026: wants an efficient broad-universe value screen for names that need no variant view (developing a variant view takes him a lot of time per name) — automatically filter out value traps, then check whether a catalyst can unlock the value; wants to settle which parts agents automate, which need him in the loop, and what data to prepare; starting markets: China (A and H shares), Taiwan, Japan, Korea and the US; sets no minimum daily trading value; finds a full ten-year Capital IQ export of the whole universe too heavy and is considering screening inside Capital IQ and exporting only the screen
